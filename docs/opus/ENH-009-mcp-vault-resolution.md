# ENH-009 — Serve vault resolution through parsidion-mcp

## Goal
Eliminate the duplicated vault-resolution contract (Python `resolve_vault` + TS `resolveVault`) by serving resolution authoritatively from the parsidion-mcp server, so the visualizer (and any future non-Python client) resolves vaults the same way the hooks do — removing the drift class flagged by ARC-007 and SEC-P001.

## Current-state context
- `skills/parsidion/scripts/core/vault_path.py:340` `resolve_vault()` is the authoritative resolver (explicit → `cwd/.claude/vault` → `CLAUDE_VAULT` env → default; allowlist-hardened after SEC-P001).
- `visualizer/lib/vaultResolver.ts:174` `resolveVault()` is a **narrower** allowlist reimplementation (named vaults from `vaults.yaml` + default only; no `.claude/vault`/`CLAUDE_VAULT` channels). A user who sets `CLAUDE_VAULT` sees a different vault in the visualizer than in their hooks.
- Parity is policed by `tests/fixtures/parity/vault-resolution.json` + `tests/test_vault_resolver_parity.py` + `visualizer/lib/vaultResolver.parity.test.ts` — but the two implementations genuinely differ.
- `parsidion-mcp` already runs Python, already depends on `parsidion[search]` (editable), and already wraps `vault-stats`/`vault_search` via subprocess — it can call `resolve_vault` directly.
- The CLAUDE.md already names this as the documented long-term plan.

## Step-by-step implementation
1. **Add an MCP tool `vault_resolve`** in `parsidion-mcp/src/parsidion_mcp/tools/ops.py` (next to `vault_health`): accepts optional `cwd` and `explicit` args, imports `resolve_vault` from the installed `parsidion` core, returns `{vault: <path>, source: <which-precedence-branch>, named: <bool>}`. Register it in `server.py` via `mcp.tool()` (tool count 8 → 9 — update `docs/MCP.md` and both READMEs, see DOC-003 for the existing 7→8 fix; this becomes 9).
2. **Wire the visualizer to call it**: in `visualizer/lib/vaultResolver.ts`, replace the local `resolveVault` allowlist logic with a call to the MCP tool (the visualizer already shells out to Python scripts via `runScript.ts` / `vaultStatsServer.ts`; either call `parsidion-mcp` directly or shell out to a tiny `vault_resolve` CLI). Keep a thin local fallback (default vault) only if the MCP server is unavailable.
3. **Delete the duplicated TS allowlist** (`vaultResolver.ts:156-200`) once the MCP call is the primary path; keep `realpathAllowingMissing`/`guardPath` (those are path-containment guards, not resolution).
4. **Update the parity contract**: `tests/fixtures/parity/vault-resolution.json` now pins the single resolver's behavior. The TS parity test (`vaultResolver.parity.test.ts`) becomes a test that the visualizer's MCP-call result matches `resolve_vault` (or is deleted in favor of an MCP-tool test). Add MCP test coverage in `parsidion-mcp/tests/`.
5. **Document**: update `docs/MCP.md` (tool list), `CLAUDE.md` (the "long-term plan" note becomes "done"), and the ENH-005 note in ARC-007.
